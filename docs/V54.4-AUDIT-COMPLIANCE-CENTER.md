# V54.4 — Audit & Compliance Center

## Delivered scope
- SQLite-backed administrative audit event table.
- SHA-256 hash chain linking each event to the previous event.
- Database triggers reject UPDATE and DELETE statements against audit event rows.
- Owner and Compliance can read paginated audit events and verify the chain.
- Finance is denied access to audit endpoints.
- Successful Owner Console permission checks are logged by role and permission; denied attempts are recorded without storing bearer tokens.
- Owner Master Console displays recent event time, actor role, action, resource, outcome and abbreviated event hash.

## API
- `GET /api/v1/owner/audit/events?limit=100&before_sequence=<sequence>&action=<exact-action>`
- `GET /api/v1/owner/audit/verify`
- Both require the `audit` permission and are read-only.

## Important limitations
- Current automatic event capture covers Owner Console report access and denied Owner Console access attempts. It does not yet comprehensively capture customer logins, customer trading actions, API-key lifecycle changes, configuration changes, deployment actions or external partner activity.
- Hash chaining and SQLite mutation-blocking triggers are tamper-evident controls, not true immutable/WORM storage. A privileged database operator could replace the database or remove triggers.
- Production-grade audit retention requires exporting events and chain checkpoints to independently controlled immutable storage, with access separation, retention policy, backup and alerting.
- No claim of regulatory approval or compliance certification is made.
- All Owner Console APIs remain read-only. Live trading, deposits, withdrawals and custody operations remain disabled.

## Verification
Unit tests cover append/verify, update/delete guards, hash tampering detection and action filtering/pagination. Route tests cover Owner/Compliance access, Finance denial and pagination validation. Keep PR in Draft until CI and human review pass.
