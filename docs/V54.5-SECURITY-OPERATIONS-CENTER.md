# V54.5 — Security Operations Center

## Implemented
- Customer registration success and rejected duplicate/validation attempts are recorded.
- Customer login success, failed credentials and validation failures are recorded.
- Customer Binance API credential connect and disconnect actions are recorded.
- Event metadata contains internal user ID, user-agent (truncated) and a keyed IP fingerprint; raw IP, passwords, bearer tokens, API keys and API secrets are not recorded.
- Owner and Compliance can read a 24-hour (configurable up to 168 hours) security summary and recent events.
- Finance role is denied access.
- Owner Master Console displays login success/failure counts, exchange API credential connect/revoke counts and recent events.

## API
- `GET /api/v1/owner/security/overview?hours=24&limit=50`
- Requires `security` permission.
- `hours`: 1–168; `limit`: 1–100.
- Read-only; does not lock accounts, revoke credentials or move funds.

## Security and privacy boundaries
- IP is keyed with AUTH_TOKEN_SECRET. Rotating that secret changes fingerprints. If the secret is unset, a non-secret fallback is used and fingerprints are not suitable for durable correlation; production must configure a unique random secret of at least 32 characters.
- The app currently uses request.client.host. Reverse-proxy forwarded headers are not trusted or parsed. Deploy behind a correctly configured trusted proxy before interpreting fingerprints as end-user IPs.
- Rate-limiter rejections that occur before auth route execution are not included.
- Device fingerprinting, geolocation, impossible-travel analysis, bot reputation, credential-stuffing detection and automated response are not implemented.
- Customer API-key events are lifecycle metadata only; secret material is never captured.
- Current telemetry is partial and is not an intrusion detection system or regulatory certification.
