# V54.0 — Owner Console Role-Based Access Control

## Roles and permissions
| Role | Overview | Customer orders | Ledger integrity | Execution reconciliation |
|---|---:|---:|---:|---:|
| Owner | Read | Read | Read | Read |
| Finance | Read | Denied | Read | Read |
| Compliance | Read | Read | Read | Read |

## Server secrets
- `ZENCRYPTO_OWNER_TOKEN`
- `ZENCRYPTO_FINANCE_TOKEN`
- `ZENCRYPTO_COMPLIANCE_TOKEN`

The legacy `ZENCRYPTO_ADMIN_TOKEN` remains accepted as an Owner token for backward compatibility. Configure unique random secrets (at least 32 characters) for each role. Role tokens are compared in constant time and are never returned by API responses.

## Owner API permission mapping
- `GET /api/v1/owner/overview`: Owner, Finance, Compliance
- `GET /api/v1/owner/orders`: Owner, Compliance
- `GET /api/v1/owner/ledger/integrity`: Owner, Finance, Compliance
- `GET /api/v1/owner/executions/reconciliation`: Owner, Finance, Compliance

## Security boundaries
All endpoints remain read-only. No role can enable trading, move funds, create ledger entries, or change platform configuration. Finance cannot access customer order-level details. Role tokens must be provisioned through the hosting provider's secret manager; never place them in frontend source, browser storage, repository files, logs, or screenshots.
