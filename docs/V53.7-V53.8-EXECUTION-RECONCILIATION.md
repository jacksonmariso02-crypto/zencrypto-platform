# ZenCrypto V53.7–V53.8 — Execution Event and Reconciliation Foundation

## Added
- Normalized provider execution-event persistence with exact Decimal quantities, prices and fees.
- Unique constraints for provider event IDs and execution IDs.
- Idempotent replay for identical events; conflicting reuse of either identifier is rejected.
- Read-only reconciliation between provider execution aggregates and local customer order snapshots.
- Quantity, gross-value, fee-by-asset and unmatched-provider-order reporting.
- Owner endpoint: GET /api/v1/owner/executions/reconciliation?limit=250.

## Important boundaries
- This is a storage and comparison foundation, not a provider webhook endpoint. Do not accept external events until the selected provider's official signature specification, replay protection and event schema are implemented and tested.
- Provider execution events are not settlement evidence. No customer wallet or paper ledger postings are created.
- Exact gross-value comparison may flag provider rounding differences; production tolerances must be provider-specific, documented and approved.
- Unmatched events must be investigated; never infer customer ownership from a provider order ID alone.
- Live trading, custody, deposits and withdrawals remain disabled.
