# V55.3 — OIDC Authorization Code Exchange Foundation

## Implemented
- `exchange_authorization_code()` uses an operator-selected HTTPS token endpoint, HTTP Basic confidential-client authentication and an authorization-code POST with PKCE verifier.
- Requires matching configured issuer, fixed client identifier and redirect URI from a previously consumed transaction.
- Rejects cross-host token endpoints, userinfo, query parameters, HTTP and nonmatching ports.
- Validates the returned signed ID token and binds its nonce to the original OIDC transaction.
- Uses an eight-second HTTP timeout, no redirect following and a 64 KiB response limit.
- Unit tests cover successful identity inspection, nonce mismatch, invalid endpoints, missing ID tokens and client-secret requirements.

## Not implemented
No browser login endpoint, OAuth callback route, browser session cookies, token storage, logout, user-role mapping, MFA enforcement, Owner permission changes, independent approvals or operational execution. This module is not wired to a live IdP and does not grant administrative privileges.

## Security work before use
- Confirm exact issuer and token endpoint against trusted IdP discovery, and configure both from the operator's deployment system.
- Enforce network egress policy and IdP DNS/IP restrictions to mitigate SSRF, plus proxy/TLS configuration review.
- Use a distributed, atomic, browser-session-bound transaction store (the existing PKCE store is process-local).
- Implement CSRF-protected callbacks, secure session cookies, IdP-managed MFA and per-person role assignment.
- Add token endpoint issuer policy, client rotation, revocation, replay protection, and independent security testing.
