# V54.3 — Risk & Alert Center

## Scope
Adds a read-only operational risk summary for Owner and Compliance roles. The endpoint aggregates only evidence already available in platform databases and readiness checks.

## API
- `GET /api/v1/owner/risk/alerts`
- Requires the `risk` permission.
- Owner and Compliance roles are authorized.
- Finance is intentionally denied access to the risk endpoint in this release.
- No query parameters or state-changing actions.

## Alert sources
- Wallet ledger integrity: missing schema, invalid/incomplete journals, unbalanced postings, orphan postings, invalid amounts and negative customer-available balances.
- Platform readiness: configured readiness checks explicitly returning false.
- Customer order state: UNKNOWN, SUBMITTING, RECONCILIATION_REQUIRED and PARTIALLY_RECONCILED.
- Provider execution reconciliation: mismatched local/provider fills and unmatched provider executions.

## Severity
- Critical: ledger integrity issues and provider execution mismatches.
- High: readiness failures, pending customer order reconciliation and unmatched provider executions.
- The overall risk level is the highest severity among currently generated alerts.

## Safety and limitations
- The endpoint is read-only and never freezes accounts, cancels orders, moves funds, changes API keys or posts ledger entries.
- Alerts are not a complete security monitoring product. Login attempts, IP/device reputation, API-key usage and credential changes are not connected to the current telemetry; this is disclosed in the API response and UI.
- No alerts means no issue was found in the monitored sources, not that the platform is secure.
- Provider event authenticity remains a separate prerequisite. This report does not authenticate provider payloads or treat events as settlement proof.

## UI
Owner Master Console shows alert totals, severity, category, evidence summaries and monitoring limitations. Finance role does not request the restricted risk endpoint.
