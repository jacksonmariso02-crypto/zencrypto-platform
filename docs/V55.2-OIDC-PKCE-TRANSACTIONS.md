# V55.2 — OIDC PKCE Transaction Primitives (not yet a login service)

## Implemented
- `OIDCPKCETransactions` generates cryptographically random OAuth state, OIDC nonce, PKCE S256 code verifier/challenge.
- Produces an authorization URL with `response_type=code`, `scope=openid`, `code_challenge_method=S256`.
- Bounded, process-local pending transaction storage; default 300-second expiration, 500 maximum pending requests, lock-protected single-use consumption.
- Callback transaction consumption requires exact expected issuer and rejects expired/replayed state.
- `verify_workforce_token(..., required_nonce=...)` supports constant-time nonce binding to the original transaction.
- Unit tests cover challenge generation, nonce binding, expiry, replay, issuer mismatch, invalid URLs and queue capacity.

## Security boundary
These are **internal primitives only**. No public login/callback endpoints, authorization-code exchange, browser cookie/session issuance, workforce role assignment, MFA verification or Owner permission escalation have been added.

The in-process transaction store is not production-safe across multiple workers or restarts; it must be replaced by a shared atomic TTL store, bound to a browser session, before enabling an actual callback.

## Production requirements
- Operator-approved IdP issuer, fixed redirect URI allow-list and registered confidential client.
- Authorization Code + PKCE callback implementation with browser session binding and CSRF protection.
- Secure back-channel token exchange, nonce verification, JWKS rotation and ID-token replay controls.
- Distributed single-use state store, revocation, logout and secure cookie session management.
- MFA policy attestation and per-person RBAC, independent approver checks, audit and security review.

No live trading, funds, custody or administrative change execution is enabled.
