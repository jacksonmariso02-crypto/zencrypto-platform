# V55.1 — Optional Workforce OIDC Identity Verification Foundation

## Implemented
- `workforce_oidc.py` validates RS256 JWT signatures against operator-supplied JWKS, with fixed HTTPS issuer, audience, subject, exp/iat/nbf, key identifier, key strength, algorithm restrictions and token length bounds.
- `GET /api/v1/workforce/identity-session` verifies a workforce identity token when configured, otherwise returns HTTP 503.
- Tests cover valid signatures, altered signatures, invalid issuer/audience, expiry, future issuance, invalid subject, future nbf, multi-audience authorized party, and unsupported algorithm.

## Configuration (secret manager, never repository)
- `ZENCRYPTO_WORKFORCE_OIDC_ISSUER`: exact HTTPS issuer.
- `ZENCRYPTO_WORKFORCE_OIDC_AUDIENCE`: exact audience/client.
- `ZENCRYPTO_WORKFORCE_OIDC_JWKS_JSON`: pinned public signing key set; update through controlled key rotation.

## Strict boundary
This is a cryptographic identity **inspection** endpoint, not a login UI, OAuth authorization-code flow, session store, MFA enrollment, RBAC integration or dual approval system. It does not grant Owner privileges, verify MFA, change role tokens, approve requests, execute account changes, enable custody, or route live trades.

The legacy Owner role bearer-token authorization remains unchanged. Token `amr`/`acr` values are intentionally not trusted as sufficient proof of phishing-resistant MFA until a vetted IdP policy integration is implemented. JWT replay/revocation and multi-tenant issuer/audience policy require further design.

## Before production
Add vetted OIDC Authorization Code + PKCE, browser session management with CSRF protection, per-person authorization mapping, revocation and key rotation, MFA enforcement through the IdP, replay controls, independent approval identity checks, immutable decision records and external security review.
