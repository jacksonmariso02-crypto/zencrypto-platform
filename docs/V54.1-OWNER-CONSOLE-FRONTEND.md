# V54.1 — Owner Master Console Frontend

## Scope
The exchange frontend now contains a dedicated Owner Console navigation entry and a read-only dashboard backed by the Owner APIs.

## Authentication
- The operator chooses an access profile (Owner, Finance or Compliance) and supplies the matching server-issued role token.
- The token is kept only in React component memory. It is not written to localStorage, sessionStorage, URLs or the public account API.
- Closing or clearing the page clears the token from component state.
- The backend is authoritative. Choosing a UI role does not grant permissions; the bearer token's server-side role determines access.
- The API URL is the configured exchange connector URL. No admin secret is embedded in the frontend build.

## Dashboard data
- Connected exchange account count.
- Customer order request counts and reconciliation-required count.
- Internal ledger journal and entry counts.
- Paper-trading orders, trades and accounts.
- Partner, custody, deposit, withdrawal and live-routing readiness flags.
- Release readiness checks.
- Recent customer order requests (only where the token's role permits).
- Ledger integrity report.
- Execution reconciliation summary.
- Operational warnings returned by the API.

## Role limitations
Finance tokens are expected to receive HTTP 403 for the customer order list. Owner and Compliance tokens can read that list. All reports are read-only.

## Deployment checklist
1. Deploy the matching exchange-service backend containing V54.0 role authorization.
2. Configure unique random secrets in the backend host's secret manager: ZENCRYPTO_OWNER_TOKEN, ZENCRYPTO_FINANCE_TOKEN, ZENCRYPTO_COMPLIANCE_TOKEN.
3. Retain ZENCRYPTO_ADMIN_TOKEN during migration if existing Owner access still uses it.
4. Set VITE_EXCHANGE_API_BASE_URL to the deployed exchange connector URL during the frontend build.
5. Verify CORS allows the frontend origin and Authorization header.
6. Sign in to the Owner Console using the matching role token and verify allowed and denied endpoints.
7. Keep the PR in Draft until CI and an independent security review pass.

## Explicit non-goals
This dashboard does not implement MFA, user provisioning, token rotation, audit event creation, custody reconciliation or live order controls. It does not make the platform approved to operate as a regulated exchange. Live customer order routing, deposits and withdrawals remain disabled.
