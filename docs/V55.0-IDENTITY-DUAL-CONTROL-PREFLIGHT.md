# V55.0 — Production Identity & Dual-Control Preflight

## Scope
Read-only Owner-only inventory of eight production identity, independent approval, execution and audit controls. This is a **fail-closed preflight**, not an implementation of an identity provider, MFA or approval engine.

## Endpoint
`GET /api/v1/owner/identity-preflight` requires Owner authorization. Finance and Compliance are denied.

Returns role-token presence as booleans (never tokens), control requirements and explicitly unverified states, unsafe enabled feature flags, and `production_ready=false`, `execution_authorized=false`, `dual_approval_supported=false`.

## UI
The Owner Change Request panel displays the 0/8 verified controls, missing identity prerequisites, and any unsafe feature flags.

## Safety invariants
- A configured Owner/Finance/Compliance token does not prove individual identity, phishing-resistant MFA or independent approver identity.
- No approval, KYC action, customer account mutation, permission change, configuration mutation or funds transfer is implemented.
- No controls can be marked verified through this API.
- Never expose secret values or accept user-supplied claims of MFA completion.
- Existing feature flags are reported, not changed.

## Future integration
1. Deploy a real workforce identity provider (OIDC with PKCE, per-person sessions and phishing-resistant MFA).
2. Verify signed ID tokens and authorization claims server-side, with strict issuer/audience/nonce/expiry validation.
3. Require two distinct authorized human principals for sensitive decisions, with separation of duties and replay protection.
4. Store signed, append-only decisions in independently managed retention.
5. Put a separate policy-verifying execution worker behind approvals; never execute directly from a dashboard request.
6. Complete security, legal and regulatory readiness review before production funds or trading.
